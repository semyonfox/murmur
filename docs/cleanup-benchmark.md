# Cleanup model benchmark

Tested 26 September 2026 through OpenRouter with a provider key configured as BYOK. Both runs sent the same 23 synthetic transcripts to each of five models once. The first used the original neutral 3/5 formality prompt. The second used a revised prompt that explicitly preserves deliberate emphasis, treats dictated questions as speech, and leaves ambiguous spoken numbers alone. The saved results are in the ignored local files `evals/private/cleanup-openrouter-20260926T222447Z.jsonl` and `evals/private/cleanup-openrouter-20260926T223356Z.jsonl`.

The default prompt changed again on 27 September after live dictation showed unwanted synonym swaps and excessive formality at Natural. The new prompt tells every formality level to keep the speaker's own wording; a new synthetic fixture protects “with a bit of” from becoming “with a touch of.” The numbers below describe the earlier prompt, not the revised build. Model-level accuracy and latency for the new prompt have not yet been measured.

The runner used `temperature: 0`, a 1,200-token output cap, streaming, and `reasoning: {"enabled": false}`. "First text" is elapsed time from the HTTP request to its first nonempty text chunk; total time includes the complete stream. Both include network and OpenRouter routing time. Murmur currently makes non-streaming cleanup requests, so these are comparative benchmark timings rather than measured in-app cleanup latency. The revised p90 is the 21st-fastest of 23 requests per model. Each case ran once, so these timings show this workload, not stable service latency. No audio capture, STT, or direct SiliconFlow request was measured.

All 230 requests succeeded, reported `is_byok: true`, and reported zero reasoning tokens. OpenRouter's `usage.cost` was zero, while `usage.cost_details.upstream_inference_cost` summed to $0.017367 for the original prompt and $0.019623 for the revised one. These are OpenRouter-reported upstream costs, not verified SiliconFlow invoices or final bills. Input tokens rose from 51,445 to 60,323 with the longer prompt; output tokens were 1,397 and 1,389. The revised run's reported upstream cost was about 13% higher. Short dictations make prompt length a real cost factor. [OpenRouter's BYOK documentation](https://openrouter.ai/docs/guides/overview/auth/byok) explains who bills the provider usage and how keys are routed.

Manual review matters more than the lexical flag counts. The revised prompt fixed the intentional "really really" emphasis in all five outputs and made the 9B model return "What is the capital of France?" instead of explaining why it would return nothing. DeepSeek and Kimi also kept "eleven twelve" as spoken. Both Qwen 9B and 35B still changed it to `11:12`; Qwen 122B changed it to `11/12`. The checker misses meaningful mistakes: DeepSeek has zero revised lexical flags but still repeats the same Hyprland point in the long-rant case. Kimi reduced "the slide should say thank you for watching" to "Thank you for watching," dropping the instruction to put it on the slide. Qwen 122B still split the preferred spelling `OghmaNotes` into two words, and its revised long-rant output reintroduced a repeated point. Qwen 9B consolidated that point, but its revised output changed "do not enable the feature" to "do not enable it."

`Qwen3.5-35B-A3B` remains the provisional default candidate for Murmur's cleanup. It was the only model that consolidated the long repeated point in both runs while keeping all three substantive requirements and the preferred technical spelling. Its revised median total time was 1.34 seconds with a 1.54-second p90 in this small sample. Its continued `11:12` guess is a real semantic error, so this is not a production quality verdict. DeepSeek V4.1 Flash is the cheaper challenger if another prompt change can remove repeated thoughts without losing its restraint on ambiguous numbers. Test real STT errors, longer rants, and repeated runs before fixing a default. Lexical flags are review prompts, not accuracy scores; they also flag harmless numeric variants such as `4,096` versus `4096`.

Murmur should send this configured route to OpenRouter. The SiliconFlow BYOK key, provider order, and failover are configured inside OpenRouter. Direct SiliconFlow remains an optional, separately selected provider, with no automatic app-level fallback. Read-only [generation metadata](https://openrouter.ai/docs/api/api-reference/generations/get-generation) lookups for the first revised request from each of the five models returned `provider_name: SiliconFlow` and `is_byok: true`. That verifies five sampled routes. The saved benchmark rows do not contain provider metadata, so these checks cannot prove the route of the other 110 revised requests or the original run. OpenRouter's [BYOK routing rules](https://openrouter.ai/docs/guides/overview/auth/byok) permit shared-capacity fallback by default unless configured otherwise. The five model IDs appear in both the [OpenRouter](https://openrouter.ai/models) and [SiliconFlow](https://www.siliconflow.com/models) catalogs; catalog prices can change.
