# Android client

Murmur has a native Kotlin Android client. On Android 13 and newer, an optional voice bubble appears beside a focused, editable field while the user's usual keyboard remains selected. The idle control is a compact microphone icon; drag it to move it or tap to start recording. It expands for recording and transcription, with Done and × actions. Input settings save its size, opacity and position. There is no Murmur keyboard. Phones older than Android 13 can still record lectures and transcribe audio files but cannot dictate into other apps. See the [setup and build guide](../apps/android/README.md).

## Current dictation path

1. In Murmur, set an STT endpoint and model, save a key if needed, and allow microphone access. The default is OpenRouter's /audio/transcriptions endpoint with openai/whisper-large-v3-turbo. The client sends a temporary WAV recording as an OpenAI-style multipart request and expects JSON containing text. It accepts HTTPS endpoints and HTTP only on the phone's own loopback address. A PC's localhost is not the phone's localhost. [OpenRouter STT guide](https://openrouter.ai/docs/guides/overview/multimodal/stt), [Android network security configuration](https://developer.android.com/privacy-and-security/security-config).
2. For the bubble, accept the in-app Accessibility disclosure and enable **Murmur voice bubble** in Android settings. Then return to the visible Murmur activity and tap **Turn on voice bubble** in the Home status card. This starts a microphone foreground service and posts a notification with a Stop action. Android restricts starting this service from a background bubble because microphone access is a while-in-use permission. [Foreground-service restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start).
3. Focus an ordinary text field. The service checks the focused node and editor type before showing its compact accessibility overlay above the detected keyboard. Dragging saves a position within the visible space above the keyboard; rotation or a keyboard change clamps it back into view. It suppresses the bubble in password, number, phone, and fields marked to disable personalized learning. Its TYPE_ACCESSIBILITY_OVERLAY does not need the separate draw-over-other-apps permission. [Accessibility service guide](https://developer.android.com/guide/topics/ui/accessibility/views/service), [overlay window type](https://developer.android.com/reference/android/view/WindowManager.LayoutParams).
4. The recorder captures up to two minutes of audio. After transcription, Murmur checks that the focused node and editor still match the recording target, then sends text with AccessibilityInputConnection.commitText. It reads cursor context for spacing but does not send existing field text to the STT endpoint. The latest raw transcript stays recoverable if the target changed or the send failed. Android does not return an insertion-success result from this API, so on-device testing must verify that apps actually accept the text. The Android 13 accessibility input method API is why the bubble has an Android 13 minimum. [Accessibility input method API](https://developer.android.com/reference/android/accessibilityservice/InputMethod), [commitText API](https://developer.android.com/reference/android/accessibilityservice/InputMethod.AccessibilityInputConnection).

Version 0.1.19 removed the Murmur keyboard fallback so dictation has a single path to make reliable.

Android may block Accessibility for a sideloaded APK until the user opens **Settings → Apps → Murmur → More → Allow restricted settings**. The user should only do this for an APK they trust. [Android restricted settings](https://support.google.com/android/answer/12623953?hl=en). A Google Play release needs an accurate Accessibility API declaration and prominent disclosure and consent; the current setup screen supplies the disclosure, but Play review has not happened. [Google Play Accessibility policy](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en).

## Lecture and audio-file path

Lectures is a top-level tab with **Record** and an import action. Recording runs in a microphone foreground service. The full-screen recorder shows elapsed time and a live level meter fed from the capture loop, and supports pause, resume, finish and discard. Pausing keeps the microphone open and drops audio, so resuming is instant and the paused span is absent from the file. The notification carries a chronometer and Pause or Resume and Finish actions. The service publishes its phase, part progress and level history as state flows instead of status strings. Android decodes imported files to 16 kHz mono WAV. Both paths cap audio at eight hours, store it in app-private storage, and transcribe two-minute parts with the selected downloaded model or endpoint. Optional cleanup receives each text part after its raw transcript is saved. The lecture screen plays the audio, seeks from each part's timestamp and switches between cleaned and raw text. The app retains partial text and audio after a failed request, with a manual Transcribe again action. Retry on a cloud endpoint can create new provider charges. Saved audio can be shared separately and the JSON export contains text only. The phone's installed speech recognizer cannot process saved audio.

## Request deadlines and diagnostics

A hosted transcription request waits 15 seconds plus the clip length, between 20 and 120 seconds, instead of a flat two minutes. Cleanup waits 20 seconds plus a little per character, up to a minute, and falls back to the raw text. A quick connection failure, a 5xx or a 429 is retried once. Timeouts and missing connectivity are not, and a live piece that fails that way no longer sends the whole take again. A lecture part on a cloud endpoint gets one more try after five seconds. `Diagnostics.kt` writes a rotating log of about 512 KB in app storage with failures, crashes, Android's recorded exit reasons and timings, and the user can share or clear it from About.

## Data and model limits

The [model-settings parity table](android-model-parity.md) maps the desktop controls to Android and records platform-specific limits.

The Android app offers the system's on-device recognizer when available, a selectable downloaded Whisper or Parakeet model, or a configured speech endpoint. Parakeet TDT 0.6B v3 comes from `ggml-org/parakeet-GGUF` at revision `35156454d1a39de06863303dd209fd2bed6ee079`, converted from NVIDIA's `nvidia/parakeet-tdt-0.6b-v3` weights, which NVIDIA publishes under CC-BY-4.0. Parakeet attends over the whole clip, so the app feeds it pieces of at most 20 seconds split at the quietest point; on a server CPU, 33 seconds took 8 seconds but 8 minutes in one pass took 9 minutes and 7 GB. Settings has separate Recognition and Transcript cleanup screens with visible status. Cleanup supports provider presets including Anthropic's Messages API, model discovery, custom instructions, formality and optional local filler removal. A cloud cleanup provider receives transcript text and dictionary entries; a speech endpoint receives audio only when selected. Raw text remains recoverable in history, and the last cleanup failure is shown on the Cleanup screen. Local recognition does not silently switch to cloud. The app encrypts BYOK keys per endpoint URL with Android Keystore AES-GCM. Short dictation WAV files are deleted after processing. Lecture WAV files stay in private storage for retry and sharing until their retention period ends or the user deletes them. A compatible service on another machine needs HTTPS; a phone's `localhost` is not a desktop server.

OpenRouter's cleanup-model routing does not establish where a speech request runs. Its STT guide says BYOK is supported, but provider.order, only, and ignore preferences do not apply to transcription requests. Do not claim that the current Whisper request runs on SiliconFlow without checking the actual STT provider route. [OpenRouter STT routing notes](https://openrouter.ai/docs/guides/overview/multimodal/stt).

The installed [on-device SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer) cannot select or inspect its model and does not work on every phone. The separate native Whisper path offers four downloadable model sizes. Files are pinned by revision, byte length and SHA-256, and no cloud fallback is made if a local model fails. The Tiny file was checked against the hosted bytes; the other catalog hashes still need independent download checks. Accuracy, latency, memory, battery and long-lecture performance need physical-device measurement. The [model study](research/models-and-cleanup.md) covers other candidates.

Cleanup now has a separate text stage, preferred-spelling dictionary and five formality levels, but its prompt and output checks still need an on-device quality evaluation against the desktop fixtures. The app stores raw and final text in SQLite with optional 7, 30 or 90 day retention and user-triggered JSON export. Home shows retained words, current-week words, recorded WPM and minutes, eight weeks of word totals and weekly pace. Spoken WPM uses raw words and recorded duration, including pauses. Lecture audio retention, retranscription and playback are available. Compressed archive export and separate STT/cleanup usage accounting remain to be built. The [data and stats contract](data-and-stats.md) describes the intended fields.

## Verification still needed

The source and build instructions are in the [Android app README](../apps/android/README.md). A successful Gradle build, unit tests, or lint cannot establish that the accessibility bubble behaves correctly across Android devices. On an Android 14/API 34 x86_64 emulator, the popup stayed above the stock keyboard, captured a 488,810-byte WAV, sent it to a loopback mock STT endpoint, and inserted the mock transcript at the cursor. The bubble stayed hidden in an Android Wi-Fi password field, and the [recording pill](screenshots/android-popup-api34.png) showed its full timer and Done action. This run used no real keys or external API calls.

Physical arm64 coverage and the Gboard/app matrix remain pending. The lecture service, long microphone capture, imported audio decoder, screen-off operation, retention and retry path also need device testing. Test bubble dragging, opacity and size changes, Gboard and another keyboard, Chrome/WebView, chat composers, password and numeric fields, selection replacement, editor switches during transcription, rotation, split screen, floating keyboards, permission revocation, no network, notification Stop, and force stop. Verify the bubble's position above each keyboard and that stale results never reach a different field. [Android command-line testing](https://developer.android.com/studio/test/command-line), [device testing](https://developer.android.com/studio/run/device).
